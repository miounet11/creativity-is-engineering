# 定律：三张皮，一层肉

控制面一旦长大，会同时出现：

- 窗口里的 IPC
- 本机 HTTP（给外部 agent）
- 测试里的直接函数调用

三套入口如果各自写业务，创造力会变成三份互相漂移的补丁。

## 收敛规则

写操作必须进 service。HTTP 和 IPC 只做鉴权、取参、调用。测试可以直调 service，但必须走同一份 `normalize` / 白名单 / 审计追加。

禁止：为了「方便」在 renderer 或路由里手改状态文件。

## 长跑壳不是 fork

长期机面板如果复制一份脚本再改，两周后桌面和农场会变成两个产品。正确关系：

- 脚本 = 业务循环
- 面板 = 监督、配置、托盘、STOP
- 配置解析 = 纯函数，Electron 和不带窗口的 Node 都能 import

## Identity 也是整合

设备、网络、语言、身份提示、行为预设、生命周期必须在**创建时**打成原子 bundle。启动时再补，操作者已经造出「深圳锚点 + 北京号码 + 上海出口」这种 internally 打架的档案。

整合发生在写入磁盘之前，不是发生在第一次请求之后。
