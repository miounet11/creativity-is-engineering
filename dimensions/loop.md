# 纬度：创造会话七步

配套：[land](./land.md) · [taxonomy](./taxonomy.md)

怎么写代码的七步在 build-standard / ship-standard `PROBE-*`。本纬度锁的是**创造会话**：先命名定律，再最小实现。

---

## 一句话

**先要原文，再命名定律，先红后绿，收尾必须落盘。**

## 何时用

- 任何非平凡创造会话（新定律、新包装、新分类）
- Agent 准备直接改参数或加功能时

错字和注释可以不走满环，但不得借此改行为。

## 七步

| 步 | 做什么 | 产出 |
|----|--------|------|
| 1. 诊断 | 要原文、截图、计时 | 3 条缺口 |
| 2. 命名 | MUST / MUST NOT | 门禁 id 或新 id 草案 |
| 3. 计划 | P0 能单独成立 | 完成定义 |
| 4. 红 | 失败测试或未登记 id | 第一笔是红的 |
| 5. 绿 | 最小实现 | 禁止顺手重构 |
| 6. 验证 | `npm run verify` 或产品仓对应门禁 | 证据 |
| 7. 落盘 | 走 [land](./land.md) | 例子 + changelog |

跳步按流程拒，不按意图放行。

## 门禁

- [ ] `LOOP-1` 会话先要原文或计时，未定性就动手视为失败
- [ ] `LOOP-2` 定律用现在时 MUST / MUST NOT 写出
- [ ] `LOOP-3` 第一笔是红灯探针或未登记 id 的自检失败
- [ ] `LOOP-4` 实现是最小变绿，无顺手重构
- [ ] `LOOP-5` 收尾走 LAND，不把「说完了」当完成

## 禁止

- 本地能跑当完成
- 测试以后再补
- 功能变更里顺手清理邻文件

## 产出

红灯提交、绿灯提交、落盘文件。
