# 案例：域名 HTTPS 在目标网络失败

**战场：** 把 Windows 安装包和远程配置发到站点，目标机器在国内。  
**表面症状：** 面板「从 URL 加载」报 `TypeError: fetch failed`。密钥栏是空的。  
**错误判断：** 配置文件坏了，或面板 IPC 坏了。

## 取证

- 源站用域名 HTTPS 拉配置：200
- 目标机走同一域名：失败
- 源站 nginx 其实已经为「国内可能解析 / SNI 不到域名」留了 **IP + HTTP** 的 `/farm/` 回退
- 用 IP 直链拉同一文件：200，正文完整

## 判断

不是配置内容问题，是**第三条通道没写进面板默认路径**。包装清单只宣传了域名。

## 动作

1. 立刻给操作者 IP URL，不先改代码也能跑
2. 发布页和 `manifest.json` 同时列出域名和 IP
3. 下一版：URL 加载按候选列表尝试（域名失败则换 IP），错误信息带上可用镜像

## 沉淀

- [patterns/remote-config.md](../patterns/remote-config.md)
- [templates/manifest.json](../templates/manifest.json) 必须含 `*Ip` 字段
- 上线公告同时发：安装地址、配置地址、**IP 地址**、怎么停

## 创造力在哪

站点上的回退已经存在，但产品没有把它接到人会点的那个按钮上。创造是把已有的第三条路接到失败现场，而不是再写一个下载器。
