# 对照：观感在打字，杠杆不在打字

对应：`MOAT-1` `MOAT-2` `MOAT-3` `MOAT-4` `MOAT-5` `MOAT-6` `MOAT-7` `MEASURE-1` `MEASURE-2` `MEASURE-3` `MEASURE-5`

**表面症状：** 资料页姓名和密码逐字出现，人机验证尚未勾上。操作者判断卡点是输入。

**证据（成功样本分段，墙钟相减，`MEASURE-3`）：**

| 阶段 | 大约墙钟 |
|------|----------|
| 启动 | 5s |
| 打开页 | 7s |
| 邮箱阶段 | 5s |
| 一次性代码 | 29s |
| 资料页（输入与验证并行） | 42s |
| 提交后取会话 | 18s |
| 全链路 | 106s |

吞吐约 3.6/min，成功率约 93%。资料页打字约 8–12s，与验证并行，墙钟 ≈ max。把打字改成瞬间填完，全链路大约 106→97s，吞吐大约 3.6→3.9/min。没有分段数字的「感觉慢」没有进入优化清单（`MEASURE-5`）。

**对条：**

- `MEASURE-1` / `MEASURE-2`：先有分段；并行用 max，不用 sum
- `MOAT-4`：观感痛点 ≠ 吞吐杠杆
- 操作者判定「不调整，这是优势」→ `MOAT-1`，禁止清单 → `MOAT-2`
- 默认行为层保持开启，不把 `humanize=false` 或键间隔 0 当修 bug → `MOAT-6`
- 键间隔不是均匀 tick → `MOAT-7`
- 若某次调用必须关掉，只允许 per-call 覆盖并记风险行 → `MOAT-3`
- 下一会话能从本仓规则读到这条优势 → `MOAT-5`
