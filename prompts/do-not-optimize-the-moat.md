# 给 AI：不要优化护城河

当用户说某段「慢」或「笨」时：

1. 先问或先找分段计时。没有数字，只允许记录观感，不准改参数。
2. 问清楚：这是**观感痛点**还是**吞吐杠杆**。两者经常不是同一段。
3. 若这段是行为真实度、反检测、身份一致性、或用户明确说的优势——**默认不改**。
4. 若必须改，只允许 per-call override，并在风险清单记一笔「护城河被削」。
5. 用户说「那就别调整了，这应该也是我们的优势」= 最高优先级产品判断。遵守，并写进 `patterns/humanize-as-moat.md` 同类文件。

禁止：把 typing delay 调到 0 当「提效」；把 humanize 关掉当「修 bug」；用「反正能过」代替一个业务周期。
